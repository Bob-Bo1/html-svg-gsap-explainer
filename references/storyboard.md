# 分镜规划

先确定观众看完能解释什么。按真实的因果、几何变化或流程组织顺序，通常从问题或可观察现象开始，再拆解机制，最后解释条件与局限。不要把定义轮流贴到画面上充当动画。

每个点击阶段填写：

| 字段 | 内容 |
| --- | --- |
| 阶段 ID 与标题 | 短标题，对应 scene.json |
| 本阶段要说明的事 | 一个具体认知变化 |
| 讲解文字 | 适合目标观众，可用作口播或讲解提示 |
| 起始状态 | 哪些对象已在场，来自哪一步 |
| 动作 | 谁移动、旋转、缩放、拆分、连接或重组，先后关系是什么 |
| 结束状态 | 最终位置与关系 |
| 对象 | 沿用 ID、新建 ID，出现与离开的原因 |
| 点击与停留 | 一次点击触发一阶段，结束后等待 |
| 原理与简化 | 示意数字、比例、类比、假设、来源 |

同时说明画幅、配色、字体和视觉隐喻。默认横屏 16:9，其他要求以用户为准。

句子拆成 Token 时，从开始就用可独立移动的文字卡片表示。先隐藏卡片边框，让文本连续，再展开间距与边框。数学面积、物理零件和流程节点同样保持语义身份，用独立子对象演示拆分。

常见动作约 0.5–1.2 秒，复杂操作可以包含几个短动作，按知识过程安排。等待用户的时间无限。不添加没有解释作用的随机闪烁或持续漂移。

限定条件应放在可见位置，例如 LLM 概率注明示意，不能把生成流畅解释为事实可靠。
